1. Briefly summarize The Gaming Room client and their software requirements. Who was the client? What type of software did they want you to design?

    The Gaming Room was a game development studio with a popular game on the Android app store they wished to host as a browser accessible website.
   The game, Draw It or Lose It, was based on the 1980s show "Win, Lose, or Draw", and needed to accommodate functionality on different platforms,
   browsers, and even devices. The documentation outlined the nuances of the software to be developed, including necessary considerations for
   different operating systems, while hardware choices were left open. 

2. What did you do particularly well in developing this documentation?

    The best practice during this project was constant revision. Discussing operating systems, the tools on each, and how they differ from each other
   required a significant amount of research and learning about the technical topic. There were occasions where I was incorrect or off the mark, but
   through dedicated revisions I was able to progressively forge the document into a proper conclusion. 

3. What about the process of working through a design document did you find helpful when developing the code?

    When going through the actual code, I found that the documentation helped illuminate the otherwise abstract connections between classes. When
   coding, small projects can be easy to decipher, but larger projects with an equally large number of interconnected pieces makes understanding
   the broader picture exponentially harder. The documentation helped with understanding how the various pieces of the project would interact with
   each other and how they would need to function together for the program to work. 

4. If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?

    I've already done quite a bit of revision, so I'm satisfied with the end result for the most part. However, if I were to revisit it, I think
   that I would like to improve the overall structure of the text blocks. In my revisions, I added a lot of content, primarily to the end of a
   block of text, where it may not have naturally fit. These additions make some texts bounce back and forth from topic to topic, and so I would
   like to potentially reformat the text to be more naturally flowing. 

5. How did you interpret the user’s needs and implement them into your software design? Why is it so important to consider the user’s needs when designing?

    When interpreting the user's wishes, I tried to come at the problem from the perspective of a business. The client's goal was to make the game as
   widely accessible as possible in the aim of increasing their userbase and the revenue that is generated from it. Considering their desire to
   provide value to their customers in the form of a game helped me better understand the underlying goals driving the process, and comprehending the
   reasons behind a request rather than just going off of the exact wording of the request will help keep development faithful to what the customer
   truly wants. 

6. How did you approach designing software? What techniques or strategies would you use in the future to analyze and design a similar software application?

    One of the biggest software development insights I gained when taking this class was the introduction of design patterns and architectural patterns.
   When designing information systems, there are bound to be many reoccurring problems that need solving, and having a repository of well known and
   trusted solutions to those frequent issues is a great asset that I will need to employ in the future. Another reason they are so helpful is that they
   are a recognizable landmark in code, and finding them could make code I'm looking into easier to understand.
